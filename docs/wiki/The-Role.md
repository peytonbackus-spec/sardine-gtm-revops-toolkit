# The Role: Revenue Operations Manager

The [role map](https://github.com/peytonbackus-spec/sardine-gtm-revops-toolkit/blob/main/ROLE_MAP.md) maps every line of the [posting](https://jobs.ashbyhq.com/sardine/b6ca1fd5-a374-4c99-a6fd-a0c4d0859a61) to an artifact. In short:

| The posting asks for | Answered by |
|---|---|
| Own the evaluation of GTM technology for an AI-first world | [[Stack Evaluation]] |
| Analytics infrastructure for the GTM ecosystem | [semantic layer](https://github.com/peytonbackus-spec/sardine-gtm-revops-toolkit/blob/main/shared_core/metrics/sql/semantic_layer.sql), funnel and pipeline reports |
| Strategic insights | Narrative in every report; scoring calibration; forecast bias by region |
| "Vibe coding": build custom tools with AI dev tools | The repo itself: 14 runnable modules, a webhook API, AI workflows with evals |
| Automate the lead-to-cash lifecycle | [[Consumption and Lead to Cash]] |
| Partner with Sales, Marketing, Post-Sales | [[First 90 Days]] |
| APIs, webhooks, middleware; Salesforce, HubSpot, Unify, Clay, n8n | [enrichment webhook](https://github.com/peytonbackus-spec/sardine-gtm-revops-toolkit/blob/main/gtm_engineer/integrations/webhook.py), [stack map](https://github.com/peytonbackus-spec/sardine-gtm-revops-toolkit/blob/main/shared_core/context/gtm-stack-map.md) |

**Two roles in one.** Sardine also posted a separate GTM Engineer role, described as its "first GTM Engineer". The RevOps Manager posting asks for the person to act as the internal GTM Engineer, so this repo treats 🟦 and 🟩 as one owner's job. The split stays in the folders because it's still where the work divides: lead conversion.
